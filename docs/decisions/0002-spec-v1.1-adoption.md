# ADR 0002: Adopting specification v1.1 into the ongoing build

Status: accepted. Date: 2026-10-06.

## Context

Specification v1.1 (`docs/spec/suv-deal-system-build-spec.md`, section 37) adds Vasko's bounded
standing authorization for one automatic seller inquiry per verified vehicle/seller pair, the
local classic-Outlook reply worker with an Outlook -> backend -> private Slack -> dot -> MCP reply
route, cross-site lifecycle/availability evidence and a 15-day quality goal. It must be applied as
a delta to the existing build, not a restart.

## Decisions

1. **Additive slice.** New pure domain modules (`domain/inquiries.py`, `seller_templates.py`,
   `language.py`, `seller_contacts.py`, `replies.py`, `lifecycle.py`), one additive migration
   (`20261006001000_seller_inquiries.sql`) for the section 37.8 tables, provider integrations
   (`integrations/seller_email.py`), the desktop worker (`desktop/outlook-bridge/`, Python +
   pywin32 behind a guarded import) and later repositories/workers/API/MCP extensions. Existing
   components, data and tests are preserved.
2. **No approval gate.** `SELLER_INQUIRY_REQUIRE_MESSAGE_APPROVAL=false` by default and no code
   path adds a per-message or first-template approval. Sending is technically gated only by sender
   verification (`SELLER_INQUIRY_MODE=disabled_until_sender_ready` until the configured account is
   verified), recipient/language evidence, dedup reservations, rate caps (2/24 h, 5/15 days),
   suppression and the kill switch. These are safety prerequisites, not approvals.
3. **Scope is fixed.** Templates are the exact versioned texts of spec 37.4; a scope validator
   rejects commitments, extra personal data, attachments, CC/BCC or extra questions. No follow-ups,
   replies, offers, price acceptance, reservations, deposits or purchases.
4. **Scopes.** New `inquiries:read` (owner, reviewer), `inquiries:pause` (owner; may be narrowly
   granted to dot) and `mail:ingest` (mailbox-bound worker credentials only; never granted to
   system workers).
5. **Routing by event category.** Native MCP Events stays the preferred route for candidate/review
   discovery; seller replies use the Slack signal route only, never both.
6. **Language.** Precedence: verified seller preference, then seller-written ad text evidence.
   Country/navigation language is insufficient; English is never the unknown-language fallback;
   unresolved language blocks the send with `language_unresolved`.
7. **Uncertain sends never auto-retry** unless pre-submission failure is proven or the provider
   documents idempotency; reservations and quota debits are retained.

## Consequences

Activation needs: a verified sender account (provider TBD by the owner), classic Outlook on the
owner's Windows machine for the reply worker, a verified private Slack channel and dot trigger.
Until then the code is implemented and tested against synthetic doubles only (it is not
activation-complete: see `IMPLEMENTATION_STATUS.md` and `ACTIVATION_GATES.md`) and no real seller
email is sent or claimed.

## Addendum 2026-10-06: sender mailbox

The owner selected his existing personal Gmail account as the seller-inquiry mailbox (the address
is configured only in the runtime `.env` / `ops.email_sender_bindings`, never committed).
Consequences:

- Default send path: `SELLER_EMAIL_PROVIDER=outlook_local` — the same classic Outlook for Windows
  instance that hosts the reply worker sends through its configured Gmail account (`MailItem.Send`),
  so no separate Google Cloud OAuth client is needed. Inquiries wait in the backend queue while
  the laptop/Outlook is offline; offline time is reported as a coverage gap.
- Optional alternative: `gmail_api` (OAuth `gmail.send`) for sending while the laptop is off.
  Google Cloud project/consent-screen requirements and token lifetime for a personal app must be
  verified at activation (UNVERIFIED here).
- Because this is a personal mailbox, the local-matching rule is critical: only replies correlated
  to stored outbound inquiry Message-IDs leave the machine; nothing else is read into Supabase,
  Slack or any model provider.
